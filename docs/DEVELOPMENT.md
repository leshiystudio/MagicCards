# Разработка MagicCards

[← Об игре](../README.md)

## Команды проекта

Команды определены в `package.json`. Нужен Node.js 24 или новее с npm.

| Команда | Результат |
|---|---|
| `npm run dev` | Сборка и локальная игра, порт 4173 |
| `npm run build` | Статический сайт в dist/ |
| `npm test` | Сценарные проверки правил, ошибок, бота и replay |
| `npm run validate` | Проверка каталога, стартовых колод и scenarios/ |
| `npm run cli` | Диагностическая консоль |
| `npm run simulate -- 100` | По 100 партий ботов в каждой экономике, проверка каждого replay |

Эквиваленты без npm: `node scripts/serve.mjs`, `node scripts/build.mjs`, `node tests/run.mjs`. Результаты проверок сохраняются в artifacts/. Команды не публикуют сайт.

Локальный сервер обслуживает собранный клиент по HTTP. Открытие `index.html` через `file://` не поддерживается: загрузка модулей, каталога карт и Worker требует HTTP. После правок пересоберите клиент и обновите страницу.

## Архитектура

- `content/` — отдельные JSON-определения и manifest.json; это исходный контент.
- `src/content/` — компиляция компонентов, связывание способностей, проверки контента/колод.
- `src/engine/engine.ts` — чистое от файловой системы/DOM ядро, команды, DSL, стек, бой, ауры, снимки.
- `src/bot/` — эвристическая политика по разрешённому наблюдению и браузерный Worker.
- `src/web/` — стол, мастерская, сохранения; клиент не реализует собственных правил.
- `src/cli/` — консоль и runner с утверждениями.
- `fixtures/`, `scenarios/`, `tests/` — воспроизводимые проверки.
- `schemas/` — формат обмена; строгие семантические проверки выполняет компилятор контента.
- `scripts/` — сборка, локальный сервер, валидация и пакетные партии.

Сборка использует встроенный Node.js `stripTypeScriptTypes`. Это удаление аннотаций, **не** статическая проверка типов TypeScript. Внешний React/Vite не нужен; клиент написан на нативных ES-модулях, DOM и CSS.

## Диагностическая консоль

`help` выводит команды. Пример:

```text
new automatic_growth 1
show state
show legal
pass
bot
```

`cast <instance> <targets JSON>`, `activate <instance> <abilityId> <fields JSON>`, `attackers`, `blockers`, `choose` и полный JSON используют тот же execute. `debug full` явно открывает закрытые данные только в консоли. `scenario scenarios/life-cost-is-atomic.json` воспроизводит проверку атомарной оплаты.
