# Публикация MagicCards на GitHub Pages

[← Об игре](../README.md)

MagicCards собирается в статический сайт: для размещения нужен только каталог `dist/`. Игрового сервера и базы данных нет. Пути к стилям, модулям, каталогу карт и Worker относительные, поэтому клиент рассчитан на адрес проекта вида `https://<owner>.github.io/MagicCards/`.

## Рекомендуемая схема

Хранить исходники в `main`, а сайт собирать и публиковать через **GitHub Actions**. Для этого в репозитории уже есть [workflow публикации](../.github/workflows/pages.yml). Он проверяет контент, запускает тесты, собирает клиент и передаёт `dist/` в Pages как артефакт.

Отдельная ветка `gh-pages` для этой схемы не требуется. Каталог `dist/` остаётся результатом сборки и не коммитится. Ветки разработки используются для изменений и pull request; публикация выпускает проверенную версию из `main`.

## Первая публикация

1. Убедитесь, что workflow и исходники присутствуют в `main` на GitHub.
2. Откройте **Settings → Pages → Build and deployment** и выберите **Source: GitHub Actions**.
3. В **Settings → Environments → github-pages** ограничьте разрешённые ветки публикации до `main`.
4. Откройте **Actions → Publish reviewed MagicCards → Run workflow**, выберите `main` и запустите workflow.
5. Дождитесь успешных заданий `build` и `deploy`. Адрес сайта появится у окружения `github-pages` и в разделе Pages.
6. Откройте опубликованную игру: начните матч с ботом, проверьте загрузку карт и работу мастерской. После успешной публикации добавьте действительную ссылку «Играть» в README.

Текущий workflow запускается **вручную** через `workflow_dispatch`. Обычный push сам по себе не обновляет сайт. Если проверки или сборка завершаются ошибкой, задание публикации не запускается.

## Как выпускать обновления

Пока игра развивается как прототип, ручная публикация позволяет выбрать момент обновления. После проверки изменений в `main` повторно запустите тот же workflow.

Если каждое изменение в `main` должно сразу попадать на сайт, можно добавить событие push в существующий workflow:

```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
```

Это вариант дальнейшей настройки; в текущем файле автоматическая публикация не включена.

Публикация из отдельной ветки подходит, когда в ней уже хранятся готовые HTML/CSS/JS. Для MagicCards с собственной сборкой Actions проще: исходники, проверки и публикация связаны одним workflow, а сгенерированные файлы не попадают в историю Git.

Официальные инструкции: [выбор источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) и [собственный workflow Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
