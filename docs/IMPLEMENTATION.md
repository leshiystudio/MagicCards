# Фактическая реализация MagicCards

Дата проверки: 16.09.2026. Нормативный план: [MagicCards 0.14](../MagicCards/MagicCards.md).

Это рабочая локальная версия игры. Полная приёмка E8/P1 по всем сценариям раздела 12 ещё не закрыта. Наличие браузерного клиента и успешных партий не заменяет эту приёмку. Исходный план и история Obsidian не изменены.

## Что работает

- Чистое ядро на TypeScript: сериализуемое состояние, команды, детерминированный RNG, поколения ссылок, два паса, LIFO-стек, фазы, объявления атак/блоков, одновременный боевой урон, checkpoint.
- Две экономики: источники Света/Тьмы и автоматическая Энергия. Точная и произвольная часть цены, явный PaymentPlan, немедленное производство, очистка пулов.
- Составные типы, существа, артефакты, чары, Сила, броня, возвращение с кладбища, изгнание. Библиотечные способности, жетоны, ауры, подавление, вложенные эффекты, выражения, триггеры, afterResolve и отложенная реакция в бою.
- Выбор целей до оплаты и при триггере; атомарные стоимости; неизменность состояния при отказе; сохранения и replay со снимком контента.
- Бот по разрешённому PlayerView/ActionTemplate, отдельный seed политики, ограничение перебора, Worker с проверкой epoch/revision/decisionId и резервным действием.
- Браузерный стол, бот и локальная передача управления, выборы атак/блоков/целей/жертв/производства/платежа, журнал, стек, инспектор карты, save/load.
- Коллекция, проверка колоды 24 карты и лимитов копий, локальные черновики, формы карт и блоков эффектов, испытание в сценарии или матче, импорт/экспорт набора и экспорт сценария для PR.
- CLI, runner сценариев, JSON-каталог, CI и отдельный ручной workflow Pages. Публикация не выполнялась.

Каталог: 53 карты, 9 типов (включая абстрактный), 9 библиотечных способностей, 6 жетонов эффектов, 2 фишки, 3 ресурса, 3 шаблона правил, 2 пресета и 2 стартовые колоды.

## Проверки

- 73 именованные проверки в tests/run.mjs: все проходят в чистой сессии Node. Отчёт: artifacts/tests.json.
- validate: каталог, обе стартовые колоды и сценарий core:life_cost_is_atomic проходят.
- 200 партий по seed 1–100: по 100 в каждом режиме, 200 завершений, 0 технических ошибок, 0 незавершённых, 200 совпавших replay. Инварианты проверялись после каждой принятой команды. Сводка: artifacts/verification.json; подробности: artifacts/simulation-{1,26,51,76}-25.json.
- В браузере проверен путь: черновик существа 2/3 с лечением при входе → сохранить → восстановить → испытать → оплатить → два паса → отдельный триггер → save/load → экспорт сценария. Неверная сумма оплаты блокирует подтверждение; пулы игроков независимы.
- Проверены запрет третьей копии, диагностика колоды из 23 карт, скрытие руки при передаче управления, ответ Worker и сохранение человеческого окна между разделами.
- Проверены размеры 1366×768, 1920×1080 и узкая ширина 390; кнопка хода доступна у нижнего края узкого экрана. Для больших лимитов поля предусмотрена прокрутка, но отдельная визуальная приёмка всех сочетаний 32 объектов и нескольких чар ещё нужна.
- Сборка загружена по /MagicCards/ на отдельном локальном сервере: HTML, стили, JSON, модули и Worker работают в подпути.

## Открытая часть плана

1. Нет полного соответствия всем T-01–T-228. В частности, каталог EventDefinition и статическая типизация каждого поля/проекции/приватного снимка требуют расширения; текущая проверка DSL не является полной формализацией разделов 6–7.
2. Загрузчик использует единый локальный manifest с готовыми определениями. Полный протокол CardPackManifest.dependencies/requires с версиями внешних библиотек и проверкой замыкания ещё не реализован.
3. Пользовательские категории, полный ComponentRegistry со схемами метаданных и все сложные ограничения выдаваемых continuous/attachment-программ требуют дополнительной реализации и отрицательных тестов.
4. Формы мастерской покрывают обычные карты, простые ауры и вложенные if/foreach. Для сложных фильтров событий, нескольких параметризованных библиотек, производственных вариантов, общих групп оплаты и части продвинутых выражений нужен JSON. Неизменённые программы сохраняются; редактирование сложного блока формой требует сверки результата в JSON. Полный W2 round-trip ещё не принят.
5. Диагностика CLI/инспектора не покрывает все причинные цепочки, слои и происхождения из 9.7. Бот проходит базовые тактические тесты; полный набор B1 для сложных составных стоимостей и типов ещё не принят.
6. Настоящий запуск интерактивного CLI и Git-проверки через shell не выполнены: Windows-инструмент завершался до команд с ошибкой CET, запуск дочернего процесса из доступного Node запрещён средой. Экспортированные функции проектных скриптов выполнялись напрямую.
7. CI/Pages подготовлены, но не запускались на GitHub. Push/merge/релиз не выполнялись.

Эти пункты — остающаяся работа текущего плана, а не механики, перенесённые за E8/P1.

## Технологические решения

Нативные ES-модули, DOM, CSS и Web Worker вместо предварительного допущения React/Vite. Внешних runtime-зависимостей нет. Node.js 24+ удаляет TypeScript-аннотации через stripTypeScriptTypes; отдельного tsc typecheck нет. Семантику пользовательского JSON проверяет src/content, правила исполняет src/engine.

Исходники — content/ и src/. dist/ и artifacts/ генерируются и исключены из Git. Команды package.json разрешены пользователем без изменения общего реестра LSWorkspace.
