# MagicCards

Рабочая локальная версия карточной игры «Свет и Тьма»: браузерный матч против бота, передача управления двум игрокам, коллекция, конструктор колоды и мастерская карт.

Нормативный дизайн: [MagicCards.md](MagicCards/MagicCards.md), версия 0.14. Исходное хранилище Obsidian сохранено на месте. Полная приёмка E8/P1 ещё не закрыта. Фактический статус, выполненные проверки и оставшаяся работа: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

## Запуск

Нужен **Node.js 24 или новее**, с npm. Устанавливать внешние зависимости не требуется.

```sh
npm run dev
```

Открыть **http://127.0.0.1:4173**. Команда собирает статический клиент и запускает сервер только на локальном интерфейсе. После изменения исходников перезапустите команду либо выполните сборку и обновите страницу. Открытие index.html через file:// не поддерживается: ES-модули, fetch и Worker требуют HTTP.

## Команды проекта

Пользователь разрешил использовать команды этого package.json, пока проект не зарегистрирован в общем LSWorkspace/repos.yaml.

| Команда | Результат |
|---|---|
| `npm run dev` | Сборка и локальная игра, порт 4173 |
| `npm run build` | Статический сайт в dist/ |
| `npm test` | Сценарные проверки правил, ошибок, бота и replay |
| `npm run validate` | Проверка каталога, стартовых колод и scenarios/ |
| `npm run cli` | Диагностическая консоль |
| `npm run simulate -- 100` | По 100 партий ботов в каждой экономике, проверка каждого replay |

Эквиваленты без npm: `node scripts/serve.mjs`, `node scripts/build.mjs`, `node tests/run.mjs`. Результаты проверок сохраняются в artifacts/. Команды не публикуют сайт.

## Первая партия

1. Нажмите **Начать партию**, выберите экономику и соперника.
2. В режиме по умолчанию источники приходят в руку из колоды. В свою основную фазу выложите один источник; нажмите на него и активируйте производство.
3. Разыграйте карту, укажите цели и подтвердите оплату. Свет и Тьма очищаются **на границе шага**.
4. **Передать приоритет** — один пас. Два последовательных паса разрешают верхний эффект стека либо переводят к следующему шагу. Человеческие окна ответа не пропускаются автоматически.
5. В шаг атаки отметьте своих готовых существ; в шаг блоков назначьте защитников. После объявления остаётся окно быстрых ответов.
6. Победа — здоровье соперника не выше нуля. Из пустой колоды приходит возрастающая усталость.

Сохранение выгружается JSON-файлом и хранится локально. Replay воспроизводит принятые команды и проверяет итоговый хеш. В локальном режиме двух игроков экран передачи управления скрывает чужую руку.

## Авторство

**Коллекция** позволяет собрать колоду 24 карты с проверкой числа копий и совместимости ресурсов.

**Мастерская** содержит поля типов, стоимости, характеристик, свойства, эффекты, вложенные условные блоки, активации и простые ауры. Можно создавать свои типы на основе готовых, ресурсы, фишки, библиотечные способности и жетоны. Сложные определения также доступны в JSON.

**Испытать** запускает заданный сценарий либо матч с ботом с картой в колоде. Черновики и импортированные наборы проверяются перед использованием. Начатая партия хранит независимый снимок контента. В испытании кнопка **Сценарий ↓** сохраняет fixture, команды и проверяемые утверждения; этот сценарий включается в экспорт набора. Экспорт набора предназначен для проверки и обсуждения через PR; автоматической отправки на GitHub нет.

## Архитектура

- `content/` — отдельные JSON-определения и manifest.json; это исходный контент.
- `src/content/` — компиляция компонентов, связывание способностей, проверки контента/колод.
- `src/engine/engine.ts` — чистое от файловой системы/DOM ядро, команды, DSL, стек, бой, ауры, снимки.
- `src/bot/` — эвристическая политика по разрешённому наблюдению и браузерный Worker.
- `src/web/` — стол, мастерская, сохранения; клиент не реализует собственных правил.
- `src/cli/` — консоль и runner с утверждениями.
- `fixtures/`, `scenarios/`, `tests/` — воспроизводимые проверки.
- `schemas/` — формат обмена; строгие семантические проверки выполняет компилятор контента.
- `scripts/` — сборка, локальный сервер, валидация и пакетные партии.

Сборка использует встроенный Node.js `stripTypeScriptTypes`. Это удаление аннотаций, **не** статическая проверка типов TypeScript. Внешний React/Vite не нужен; клиент написан на нативных ES-модулях, DOM и CSS.

## Диагностическая консоль

`help` выводит команды. Пример:

```text
new automatic_growth 1
show state
show legal
pass
bot
```

`cast <instance> <targets JSON>`, `activate <instance> <abilityId> <fields JSON>`, `attackers`, `blockers`, `choose` и полный JSON используют тот же execute. `debug full` явно открывает закрытые данные только в консоли. `scenario scenarios/life-cost-is-atomic.json` воспроизводит проверку атомарной оплаты.

## Публикация

Результат build — статический каталог dist. Все URL относительные, включая Worker и каталог; сборка рассчитана на подпуть GitHub Pages. CI проверяет исходники; публикация запускается отдельно вручную после настройки Pages и ревью владельцем. В эту рабочую сессию push, merge, релиз и публикация не выполнялись.

Инструкции следующему разработчику: [AGENTS.md](AGENTS.md).

Конфигурация Pages основана на [официальном описании GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
